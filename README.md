# 搭子 App(曼谷华人周末搭子平台)

> 让在曼谷的华人,不用尬聊、不用攒局,点一下就能约到周末出门的伴。

## 开发

```bash
npm test              # 105 项单元测试：状态机 / 成团判定 / 报名候补 / 爬约 / 双指标 /
                      #             周末时段 / 海报布局 / 分享短码 / 注销去标识化
npm run sync:config   # 部署前必须执行：同步 rules 与 common 到各云函数
node scripts/init-db.js   # 打印建库指令
```

工程结构：`miniprogram/`（小程序端）· `cloudfunctions/`（events / signups / formation / admin）· `cloudfunctions/common/`（领域逻辑，纯函数，可测）· `config/rules.js`（规则真源）

## 结论速览

- **产品方向无需返工**。定位「零尬聊出门」与 §5「防滑向约会的结构设计」是核心资产,不受载体变更影响。
- **企业主体已就位**,PRD §4.1 的五项 V1 功能(发局、报名、成团通知、临时群聊、审核后台)全部可实现。三阶段切分保留为工程节奏选择,不再是被迫妥协。
- **手机号能拿,但不能用来发通知**:`getPhoneNumber` 返回的是微信绑定的 +86 号,不是用户在泰国能收短信的号。手机号只作唯一性锚点,通知走订阅消息。见 `docs/03` §4。
- **小程序不能分享到朋友圈**,冷启动物料必须改为**海报 + 小程序码**。见 `docs/03` §6.1。
- **备案是排期上最长的外部杠杆,但不阻塞开发**。需先确认体验版是否也需备案——这决定第一场活动是跑体验版还是退回微信群接龙。
- **跨境合规是双法域**:用户在泰国(PDPA)+ 服务器在国内(PIPL),隐私政策必须明确告知数据存储地。见 `docs/03` §8。
- **唯一的开发阻塞项**是 `docs/01` §3 的 12 项定义,每项均已给出可直接采纳的默认值。

下一步见 [`docs/03-载体决策-小程序方案.md` §12](docs/03-载体决策-小程序方案.md)。
