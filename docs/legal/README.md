# 合规文件(T30)

> ⚠️ **本目录的文件是工程草稿,不是法律意见。**
> 上线前必须由**泰国本地法务**(PDPA、线下活动责任)与**中国法务**(PIPL、UGC 平台责任)各过一遍。
> 我能保证的是:它们如实描述了代码实际在做什么 —— 每一条都能在仓库里找到对应实现。
> 法务需要判断的是措辞与充分性,而不是事实。

## 为什么是双法域

| 法域 | 适用原因 |
|---|---|
| **泰国 PDPA** | 用户是在泰国境内的自然人 |
| **中国 PIPL / 网安法** | 运营主体与服务器均在中国大陆 |

这带来一个**必须明确告知**的事实:**用户数据存储在中国大陆。**
这不是可选项 —— 跨境传输的告知义务在 PDPA 下是硬要求。

## 代码侧已落地的对应项

| 合规要求 | 实现 |
|---|---|
| 账号注销 | `cloudfunctions/account`(注销 = 抹除个人信息,保留去标识化统计) |
| 数据最小化 | `publicEvent()` 白名单投影;无任何按人检索的接口 |
| 性别用途说明 | D07 未启用自动配比,**采集用途必须写进隐私政策**,否则属瑕疵 |
| 未成年人 | 用户协议限 18 岁以上;酒馆局额外提示 |
| 举报入口 | T22(V1.5),**上线前需补齐** |
| 内容安全 | T28 `msgSecCheck` / `mediaCheckAsync` |
