## 一、发现并已修复(编号对应 security.test.js)

| # | 漏洞 | 危害 | 修复 |
|---|---|---|---|
| **S1** | **字段注入**:`genderCounts.${gender}` 的 `gender` 是用户输入且未校验枚举 | 传 `"male.x"`、`"__proto__"` 可向 events 文档注入任意字段路径,污染计数结构 | `validate.validGender` 严格枚举;`validateProfile` 在报名入口整体拦截。**这是本次审计最严重的一条** |
| **S2** | **时间注入**:发局的 `startAt` 完全未校验 | 过去的时间 → 局发出即被判解散;垃圾字符串 → `NaN` 让成团引擎对该局**永远静默跳过**,悬空无人处理 | `validISO` + 过近(判定提前量+1h)/过远(60 天)边界 |
| **S3** | **类型混淆**:`capacityMax` 非数值时 `clamp(NaN)=NaN`,名额判断恒 false;坐标、场地名、价格均未验类型与范围 | 100 人咖啡局、越界坐标、负价格、超长字符串入库 | `validateEventPayload` 全字段清洗,云函数只允许使用清洗后的 `value` |
| **S4** | **泄露面未固化**:`publicEvent` 白名单只存在于 events 云函数内部,新增字段时易被顺手带出 | `hostId`(顺着能标识用户)、`genderCounts`(诱发看人报名)、审核痕迹、`qrcodeFileID` 面临未来泄露 | 抽出 `common/projection.js`:白名单 + **禁止名单双向断言**,两名单不相交由测试锁定 |
| **S5** | **查询条件注入**:`chat.list` 的 `since` 未验类型直接进 `_.gt()` | 传对象/数组产生非预期查询语义 | `validISO` 清洗,非法值按「无 since」处理 |
| **S6** | **资源上限缺失**:局主标记数组无上限 | 超大数组拖垮循环(每项两次数据库往返) | 上限 20(= 人数硬顶的两倍冗余) |
| **C1** | **报名超卖竞态**:读→判断→写,并发抢最后名额双双成功 | 超卖;计数与实际不符 | `common/atomic.js` 条件自增为唯一权威;对撞测试 5 种子验证 |
| **C2** | **双重递补竞态**:并发取消触发同一候补被递补两次 | 计数多加、通知重发 | 占座→CAS 候补状态,失败还座重试;对撞测试验证先来后到 |
| **C3** | **重报撞唯一索引**:取消后的记录挡住重新报名 | 取消过的用户永远无法再报名 | CAS 复活已取消记录而非插入 |
| **C4** | **重报活锁**:抢到座的都 CAS 失败还座,CAS 赢家却没座 | 用户困在候补、座位全空 | 还座路径补触发递补,与取消路径对齐 |

## 二、核查通过,无需修改(均有既有测试)

| 项 | 结论 |
|---|---|
| 越权访问 admin | 每个 action 前 `requireAdmin`;非管理员一律 `forbidden` |
| 待审局泄露 | `detail`/`list` 只认 `PUBLISHED` 状态;待审/被拒按「不存在」返回(D06) |
| 群聊越权 | `canEnter`/`canSend` 校验局状态 + 本人报名状态;候补与外人进不去;归档后只读 |
| 评价越权/伪造 | `canRate` 校验参加关系、自评、重复、7 天窗口、枚举;互评永远无法触发处罚(与局主事实认定分离) |
| 身份伪造 | `openid` 由微信服务端注入(`getWXContext`),客户端不可传入;所有身份判定源于它 |
| 举报滥用 | 去重键唯一索引 + 单日 10 条频控 + 不能举报自己;举报快照防事后改帖毁证 |
| 注销完整性 | `verifyAnonymized` 断言零标识符残留;PII 清单与投影禁止名单交叉覆盖「从局反查到人」路径 |
| 前端绕过 | 数据库集合权限一律「仅管理端」,前端无直连路径;所有防线在云函数,前端校验只是体验 |
| 内容安全降级 | 按传播面分级:公开内容(发局文案/昵称)risky 即拒;群聊失败放行但留痕进复核队列 |

## 三、残余风险(已知、接受、并写明理由)

| 风险 | 为什么接受 | 触发升级的信号 |
|---|---|---|
| 无全局 API 频控(除举报外) | 云开发自带并发与配额限制兜底;V1 用户是熟人两度网络,滥用动机低 | 出现脚本刷报名/刷发局 → 加 openid 级令牌桶 |
| 管理员是单账号 | 初期管理员=Victor 本人;无多管理员审计需求 | 出现第二个管理员 → 加操作审计日志 |
| `reserveSlot` 先读 capacityMax 再条件更新 | capacityMax 发布后**无任何修改接口**,读到的值恒有效;临界资源 confirmedCount 全程只经条件更新 | 若未来加「改人数上限」功能,必须重审此处 |
| 手机号仅采集不核验 | V1 无实名能力;用途仅账号唯一性锚点(已在隐私政策声明) | 出现规模化多账号滥用 |
| 内容安全对图片(头像)未接 | V1 不采集头像(`avatarUrl` 字段预留但无上传入口) | 开放头像上传时必须接 `mediaCheckAsync` |
